## 서술

### 문제

FR-025(US-025) 목업의 「브랜드 기준」 화면을 /rules 읽기 전용 페이지로 만드는 요청이었다. 채널별 기준·금칙어·필수 표현·제품 범위 예외를 보여 주고, 빈 상태와 조회 실패를 구분해야 했다. 런은 2026-09-19 밤 04-gate 1라운드 도중 세션 종료로 끊겼고, 2026-09-20 에 next --run-id 로 재개했다.

### 원인

기존 services/rules.ts 의 resolveRules 는 생성 시점에 채널 하나에 대한 병합 결과만 만들었다. 화면이 필요로 하는 '모든 채널의 병합 결과 + 금칙어·필수 표현 목록 + 제품 예외'를 한 번에 조립하는 읽기 경로가 없었다.

### 해결

순수 함수 buildBrandStandards 를 lib/rules-merge.ts 에 더해 기존 mergeRules 를 채널마다 재사용했다. listBrandStandards 는 세 쿼리를 Promise.all 로 읽고 실패를 INTERNAL Result 로 바꾼다. 서버 컴포넌트 RulesPage 가 서비스를 직접 호출한다. 재개 뒤 04 게이트를 다시 돌려 통과했다. 05 에서는 리뷰어 4명(gen·data·test·arch)이 Major 5건을 냈고 모두 test 역할 몫이었다. test-writer 가 테스트만 보강했고 델타 재리뷰(test)에서 4건 해소가 확인됐다.

### 결과

PR #31(feat-fr-025-brand-rules-screen → main)을 생성했다. 승인은 user 가 했다. 등급은 PASS_WITH_GAPS(stage_absent:e2e, stage_na:docs)다. 05 review 는 ok(4/4)이고 07 은 clean_05 로 내장 리뷰를 생략했다. 미해결 Minor 는 ORDER BY 부재·주석 드리프트·캐스팅 등이며 보고서로 넘긴다.
