## 서술

### 문제

사용자 요청은 "must 다음 작업 확인 후 진행해줘"였다 — 구체적 기능명이 없었다. PRD/API_SPEC/TRD와 git log를 대조해 FR-001~003이 이미 구현돼 있고, PRD §8 R1의 순서(US-001~006→009~013→007·008·014)상 다음이 FR-004(제목+앵글 3안 생성, POST /api/contents/titles)임을 먼저 확정했다.

### 원인

FR-004는 TRD상 lib/validator.ts(FR-006의 순수 함수)를 직접 호출하도록 명세돼 있어, 이번 런의 범위를 FR-004 + validator.ts 선행 구현으로 잡았다. FR-005(본문 생성 전체)는 별도 범위로 남겼다 — 이전 FR들도 각각 별도 런으로 진행된 선례를 따랐다.

### 해결

01-plan에서 시간 예산 설계(초기 LLM 호출 20초 + 항목별 재생성)가 route maxDuration=30을 넘길 수 있다는 Critical을 02-cross-verify가 냈고, 01로 되돌아가 LlmClient.generateJson의 timeoutMs를 '재시도 포함 총 예산(단일 deadline)'으로 재설계해 해소했다. 03에서 impl·test 역할을 병렬 실행했고, 04 게이트·전체 회귀(137개 테스트) 통과. 05-code-review(gen·data·sec·arch 4명)에서 Major 4건(로그 purpose 필드 누락, LLM 실패 원문 미기록, 입력 길이 상한 없음, 프롬프트 인젝션 방어 부족)이 나와 impl이 수리했고, sec 델타 재리뷰로 해소를 확인했다. 06에서 사용자 승인을 받아 push+PR(#7) 생성. 07의 내장 코드리뷰(medium, 감사 런+05 수리 이력으로 강제됨)에서 새 Major 3건을 추가로 발견해 PR 코멘트로 남겼다.

### 결과

PR #7 (feat-fr-004-titles → main)이 열려 있고 머지되지 않았다. 완료 등급 PASS_WITH_GAPS(e2e·docs 스테이지가 이 스택에 없음, adapter 미검증 — 둘 다 이 프로젝트 최초 런부터 있던 구조적 사실). 05에서 열려 있던 minor 3건(data·arch·gen 각 1건)이 07 재검토에서도 여전히 미해결로 재확인됐다. 07이 새로 낸 Major 3건(프롬프트 인젝션 구분자 우회, DB 지연이 시간예산 계산에서 누락, JSON 복구 정규식의 탐욕적 매치 버그) 중 특히 인젝션 우회 건은 이미 한 차례 Critical 심사를 통과했던 시간예산 로직과 같은 종류의 결함이 다른 자리(resolveRules 구간)에 남아 있었다는 뜻이라 눈여겨볼 만하다. 승격 스캔은 후보 0건(원장이 본 런 2/9, 표본 부족).

### 배운 점

01-plan·02-cross-verify가 LLM 호출 하나의 타임아웃 예산을 촘촘히 검증했지만, 그 검증은 'LLM 호출 자체'에만 집중했고 그 앞단(DB 조회)의 지연은 같은 예산 계산에 포함되지 않았다 — 국소적으로 옳은 수정이 전역적으로는 같은 결함의 다른 사례를 남길 수 있다는 사례다. 또한 05의 리뷰어 라우팅이 예산 상한(4명)에 걸려 test 리뷰어가 빠졌는데, 07의 독립 재검토가 그 공백에서 실제 결함(프롬프트 빌더 테스트 부재)을 찾아냈다 — 05→07의 '관점을 빼지 않고 바꾼다' 설계가 이번 런에서 실제로 작동했다.

### 계약이 어디서 부족했는가

03에서 impl이 F-1 수리(로그 purpose 필드 추가) 과정에서 LlmClient.generateJson 시그니처에 purpose 인자를 추가했고, 이는 애초 계약(_workspace/contract_fr-004-titles.md)에 없던 변경이라 impl이 CONTRACT_DEFECT로 보고했다. 메인이 계약을 그 사실에 맞게 갱신(purpose 인자·실패 원문 로깅 문구 추가)한 뒤 재게이트했다 — 계약이 구현을 따라간 유일한 지점이고, 그 경위를 여기 남긴다.

### 05 리뷰 범위가 적절했는가

05는 gen·data·sec·arch 4명을 불렀고 profile 상한 때문에 test 리뷰어가 빠졌다(보고서에 남음). 소스 변경 파일(9~10개, 프롬프트 빌더·LLM 클라이언트·검증기·서비스·라우트)의 다양성을 감안하면 4관점 커버리지는 적절했으나, test 리뷰어 부재로 '프롬프트 내용 자체를 검증하는 테스트가 없다'는 결함이 05에서 걸러지지 않고 07에서야 발견됐다 — escaped_05 사례 중 하나다.
