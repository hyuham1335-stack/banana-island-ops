### 배운 점

1) 05 리뷰어 라우팅은 워킹트리(미커밋) diff 만 본다 — 05 통과 *전*에 커밋하면 리뷰어가 0명으로 라우팅돼 review05.status 가 영구히 failed 로 남는다(gaps 는 append-only, 되돌릴 수 없다). 커밋은 반드시 record --phase 05 통과 *직후*, precheck --phase 06 *이전* 한 자리뿐이다. 이 런에서 실제로 그 실수를 했고(review05:failed 가 이 런의 gaps 에 영구히 남아 있다), 커밋을 되돌려(git reset --mixed) 복구한 뒤 실제 리뷰는 4/4 정상 수행했다. 2) contract-trace 의 '## 유닛'·'## 진입점' 파서는 최상위 '- ' 불릿만 읽는다(들여쓴 불릿·'### ' 제목은 무시) — 함수 시그니처를 '### 헤딩'으로만 적으면 units=0 으로 파싱돼 already-documented 심볼도 out_of_contract 로 오탐된다. 3) entrypoint_resolver(file-convention) 는 계약의 라우트 표기를 파일 경로에 그대로 문자열 치환한다 — API_SPEC 의 사람이 읽는 {id} 표기가 아니라 Next.js 의 실제 폴더명 [id] 를 써야 한다. 4) 같은 이유로(entrypoints 는 symbols() 에 안 들어감) 라우트 파일의 POST/maxDuration export 는 '## 진입점'에 진입점으로 적어도 '## 유닛'에 별도로 다시 선언하지 않으면 out_of_contract 로 뜬다 — 이 패턴이 과거 7런에서 반복 발생했고(rules_changelog.md) 이번에도 재현·확인했다. 근본 원인이 harness 파서(수정 범위 밖)라 promote 판정은 이번에도 skip 을 유지했다.

### 05 리뷰 범위가 적절했는가

05 는 diff 규모(715줄) 때문에 fanout 모드로 gen·data·sec·arch 4명이 병렬 리뷰했다(profile normal 상한 4로 test 리뷰어는 드롭됨, 보고서에 그대로 드러남). 4명 모두 계약·기존 코드를 실제로 읽고 검증했고 major 1건(data)·minor 2건(gen 1·data 1)을 냈다 — 겹치는 관점(gen·arch 둘 다 아키텍처/계약 일치를 봄)에도 독립적으로 다른 각도(테스트 커버리지 vs 구조)에서 지적을 냈다. sec·arch 는 0건이었는데, 이 엔드포인트가 실제로 인가 로직·레이어 경계 위반 소지가 거의 없는 얇은 CRUD 성격이라 타당해 보인다.
