## 서술

### 문제

FR-020 — 제품×유통경로별 원가표를 버전으로 관리하고(작성중만 항목 전체 교체, 확정 시 잠금, 확정본 복제), 금액은 발생 통화 그대로 저장하되 개당 원화 환산은 조회 시 fx_rates 최신값으로 계산하며, 네 API 와 /costsheet 화면을 admin 전용으로 만드는 기능. 사용자가 붙여넣은 요청 원문이 일부 잘려 있어 API_SPEC·PRD·TRD 근거로 복원한 본문을 동결했다.

### 원인

05 에서 드러난 결함: (1) PATCH 의 항목 INSERT … SELECT FROM (VALUES …) 에서 batch_qty 만 캐스트가 없어 Postgres 가 text 로 확정해 integer 열에 넣지 못한다 — 항목이 있는 모든 저장이 실DB 에서 500 이 되는 critical(gen·data 합치). SQL 문자열을 렌더해 단언하는 스텁 테스트로는 잡히지 않는다. (2) 편집기 useState 가 첫 sheet 에 묶여 같은 페이지 안 이동 뒤 다른 원가표를 이전 항목으로 덮어쓸 수 있었고, 저장 후 정규형이 아닌 금액이 dirty 로 남아 확정이 막혔다. (3) 테스트가 자리표시자($1)를 문자열로 대조해 늘 참이거나 유효한 쿼리 경로를 잠그지 않았다. 04 에서는 테스트 스텁 항목 행에 costSheetId 가 빠져 게이트가 실패했다.

### 해결

04: 게이트가 ambiguous 로 impl 에 먼저 배정 — impl 이 스텁에 맞춰 프로덕션 코드에 특수 분기를 넣었으나 메인이 되돌리게 해 같은 시그니처 재발로 test 에 넘어갔고, test 가 스텁을 실제 행 형태로 고쳤다. 05: 1라운드 4인(gen·data·sec·test) → impl(캐스트)·ui(key·응답으로 상태 재설정)·test(params 위치 대조 등) 병렬 수리 → test 델타 재리뷰에서 유효 쿼리 미잠금 1건이 남아 에스컬레이션 → 사용자가 「테스트 1건 보강 후 진행」을 골라 보강 → 3라운드 4인 재리뷰에서 Critical/Major 0. 예산 초과(파일 13·14 > 10)는 사용자가 그대로 진행을 골랐고, 사용자 승인으로 PR #34 를 만들었다.

### 결과

PR #34 open, 등급 PASS_WITH_GAPS(e2e 스테이지 없음·docs 해당 없음). 미해결 Minor 11건 — 경로 id·batchQty·productId 상한 부재로 범위 초과가 500, 확정일 UTC 표시, confirm 의 중복 select, 복제 항목 순서 미보장, 재조회 null 폴백, 테스트의 일부 실패 경로·경계 미잠금. 실DB 대상 실행은 하지 않았다(미측정). 머지하지 않았다.

### 배운 점

raw SQL 로 FROM (VALUES …) 를 쓰면 파라미터가 text 로 확정되므로 목적 열 타입 캐스트가 모든 열에 필요하고, SQL 문자열을 렌더해 단언하는 스텁 테스트는 이런 타입 오류를 원리상 잡지 못한다 — 리뷰어의 SQL 정독이 유일한 방어선이었다. 게이트가 ambiguous 로 impl 에 먼저 보낸 스텁 결함을 impl 이 코드로 맞추려 한 것은 계약 없는 특수 분기를 낳을 뻔했다 — 수리 지시에 「테스트가 계약과 다르면 코드를 바꾸지 말고 보고」를 명시해도 워커가 코드를 바꿨으므로 메인이 수리 결과의 성격을 한 번 확인해야 한다.

### 계약이 어디서 부족했는가

(1) updateCostSheet 의 INSERT 형태를 '방식은 자율'로 두면서 VALUES 파라미터의 열 타입 캐스트를 요구하지 않았다 — 테스트 요구사항에도 캐스트 잠금이 없어 critical 이 04 를 통과했다. (2) 테스트 요구사항의 loadCostSheetPage 항목이 폴백 경로만 나열하고 유효한 productId·route 쿼리 경로를 명시하지 않아 에스컬레이션까지 갔다. (3) batchQty·productId·경로 id 에 int4 상한을 적지 않아 범위 초과가 500 이 된다(Minor 이월). (4) 화면 편집기의 상태 초기화(key) 요구를 적지 않았다.

### 05 리뷰 범위가 적절했는가

diff+refs 범위와 4인 fan-out 은 적절했다 — gen·data 가 독립적으로 같은 캐스트 결함을 잡았고 gen 이 화면 상태 결함 둘을 잡았다. diff 가 인라인 상한을 넘어 경로 전달로 폴백했다. arch 는 상한으로 빠졌다. 화면 단위테스트는 두지 않는 정책이라 untested_screen 은 미수행이고, 화면 결함은 리뷰로만 잡혔다. 3라운드와 에스컬레이션 1회가 있었다.

### 다음 런에서 바꿀 것

계약에 raw SQL 을 자율로 남길 때는 '모든 VALUES 파라미터를 목적 열 타입으로 캐스트'와 그 테스트 잠금을 같이 적고, 정수 입력은 int4 상한까지 스키마에 적는다. 조회 경로 테스트 요구사항에는 폴백과 함께 유효 입력 경로를 반드시 한 줄 넣는다. 클라이언트 편집 화면은 계약 「화면」에 key 로 리마운트할 식별자를 적는다. 04 수리에서 워커가 테스트에 맞춰 프로덕션 코드에 분기를 넣으면 되돌리고 게이트 재배정을 기다린다.
