## 서술

### 문제

FR-024: Apps Script 가 시트 저장 시 부르는 웹훅 POST /api/plans/webhook 이 없어서 계획 동기화가 수동(/api/plans/sync)뿐이었고, import_logs 가 수동·자동 동기화를 구분하지 못했다(listPlans 가 trigger 를 'manual' 로 하드코딩).

### 원인

FR-001 의 동기화는 수동 트리거만 전제로 설계됐고 import_logs 에 trigger 컬럼이 없었다. 웹훅 인가는 역할 쿠키가 아니라 공유 시크릿이라 기존 인가 규칙에 자리가 없었다.

### 해결

라우트 첫머리에서 SHEET_WEBHOOK_SECRET 미설정·헤더 누락·sha256 다이제스트 timingSafeEqual 불일치를 403 FORBIDDEN_ROLE(details 없음)로 거부하고, 통과 시 기존 syncPlansFromSheet 를 trigger 'webhook' 으로 재사용했다. import_trigger enum 과 import_logs.trigger(NOT NULL DEFAULT 'manual') 를 마이그레이션 0002 로 추가하고 listPlans 가 저장값을 돌려준다.

### 결과

### 배운 점

drizzle-kit 스냅샷 JSON 이 스키마 한 줄 변경에도 2400줄 넘게 붙어 precheck 줄 예산(1500)을 05·06 두 번 exit 9 로 멈춰 세웠다. 생성 산출물은 사람이 검토할 줄이 아니므로 예산 산정에서 빼는 것이 맞고, 그 전까지는 마이그레이션이 있는 런마다 같은 사람 판단이 반복된다. 또 병렬 워크트리 3개를 동시에 돌리다 세션이 끊기면 04 게이트가 stage_start 만 남긴 채 멈추는데, gate 재실행으로 문제없이 이어졌다.

### 계약이 어디서 부족했는가

계약은 importTriggerEnum 을 유닛으로 선언했지만 그 심볼을 직접 참조하는 테스트를 요구하지 않아 contract-trace 가 untested_contract_item 을 냈다. 또 거부 로그의 reason 값과 실패 봉투의 details 전달을 테스트 최소 목록에 넣지 않아 05 test/gen 리뷰어가 minor 로 지적했다.
