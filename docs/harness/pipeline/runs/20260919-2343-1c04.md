## 서술

### 문제

FR-022 — 환율(USD→KRW·PHP→KRW)을 매일 크론으로 적재하고, 실패 시 마지막 값을 유지하며, 대표가 수동 입력하고, 상단 레일에 기준일과 경과일 경고를 보이는 기능. 전 세션이 03-implement 도중 끊겨 impl 제출 JSON 이 유실되고 test 산출물이 0개인 상태에서 재개했다.

### 원인

05 에서 드러난 결함 둘: (1) impl 이 계약의 `rate: input.usdKrw / input.phpKrw`(받은 문자열 그대로)를 나눗셈으로 읽어 PHP 행에 USD/PHP 비율을 저장했다 — 응답과 DB 가 갈라지는 critical. (2) 테스트가 저장값·조회 조건을 잠그지 않아 (1) 이 04 게이트를 통과했다. getFx 조회 조건 미잠금(F-3)은 계약 테스트 요구사항이 그것을 요구하지 않은 계약 결함이었다.

### 해결

재개: `next --run-id` 로 03 패킷을 다시 받아 impl(검증·재제출)·test(신규 7파일) 를 병렬 디스패치, ui 제출은 재사용. 05 1라운드 4인이 critical 합치 → impl·test 순차 수리 → test 델타 재리뷰에서 F-3 미해소로 에스컬레이션. 사용자가 「계약 결함 의심」을 골라 메인이 계약 테스트 요구사항에 getFx ① 조건 잠금을 추가하고 test 수리 → 3라운드 4인 재리뷰에서 Critical/Major 0. origin/main(FR-024·FR-025) 머지 후 재게이트, 사용자 승인으로 PR #32 생성.

### 결과

PR #32 open, 등급 PASS_WITH_GAPS(e2e 스테이지 없음·docs 해당 없음). 미해결 Minor 는 수동 입력 정수부 자릿수 상한 부재(numeric(18,8) 초과 시 500), Frankfurter date 형식 미검증, 크론이 같은 날 수동 입력을 덮어쓰는 계약 결함, refresh 테스트의 인자·로그 미단언이다. 머지하지 않았다.

### 배운 점

계약에 `a / b` 처럼 두 값을 나란히 적는 표기는 나눗셈으로 오독된다 — impl 이 그렇게 읽었고 test 는 그 값을 잠그지 않아 게이트를 통과했다. 대응되는 값은 `USD 행 = usdKrw, PHP 행 = phpKrw` 처럼 행별로 풀어 적어야 한다. 또 계약 「테스트 요구사항」이 결과값만 적고 조회 조건 잠금을 요구하지 않으면 수리 지시가 기댈 기준이 없어 같은 지적이 라운드를 넘어 반복된다 — 에스컬레이션에서 계약 결함을 먼저 의심한 것이 맞았다. 재개 시에는 `next` 로 지문을 받은 뒤 코드를 고치면 그 라운드 record 가 exit 3 으로 튕기므로, 수리를 끝낸 다음에 `next` 를 친다.

### 계약이 어디서 부족했는가

(1) saveManualFx 의 `rate: input.usdKrw / input.phpKrw` 표기가 나눗셈으로 읽혔다 — 행별 매핑으로 적었어야 했다. (2) 테스트 요구사항의 getFx 항목이 조회 조건(`<=`·groupBy·having·orderBy·limit) 잠금을 요구하지 않았다 — 05 에스컬레이션 뒤 델타로 추가했다. (3) 크론 upsert 가 같은 기준일 수동 입력을 덮어쓰는 것을 계약이 규정했는데, 수동 값 우선 여부를 결정하지 않았다(data 리뷰어 F-5, Minor 로 이월). (4) ManualFxInput 의 십진 정규식이 numeric(18,8) 정수부 상한을 반영하지 않았다.

### 05 리뷰 범위가 적절했는가

diff+refs 범위와 4인 fan-out 은 적절했다 — 4인이 독립적으로 같은 critical 을 잡았고 sec 은 인가 순서·시크릿 비교가 계약대로임을 확인했다. arch 는 상한으로 빠졌고, ui 가 FxRailState 를 services/fx 에서 import 해 impl 이 타입 재수출을 추가한 레이어 경계 사안은 BOUNDARY_VIOLATION 검토 제외로 누구도 보지 않았다. 이 런은 3라운드까지 갔고 에스컬레이션 1회가 있었다.

### 다음 런에서 바꿀 것

계약을 쓸 때 저장 매핑은 `a / b` 대신 행별로 풀어 적고, 조회 함수의 테스트 요구사항에는 결과값과 함께 쿼리 조건 잠금을 처음부터 넣는다. 재개 런에서는 ui 가 쓴 import 경로가 계약의 export 위치와 맞는지 03 제출 전에 확인한다. 미해결 Minor 중 수동 입력 자릿수 상한(400 대신 500)과 크론의 수동 값 덮어쓰기는 다음 FR 전에 계약 결정 후 fix 레인으로 처리한다.
